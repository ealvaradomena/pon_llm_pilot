BEREC Reconstruction

Scope

BEREC is analyzed separately from the principal five-PON model comparison.

The main comparison uses IRG, EUHC, cOAlition S, CAN, and CEER under a common reconstructed step-by-step (SBS) protocol. BEREC presents a different provenance problem: a preserved historical output exists, but the exact historical interaction cannot be reconstructed with sufficient confidence to treat a new run as an exact replication.

The BEREC analysis therefore compares three distinct conditions without treating any of them as ground truth.

Three BEREC conditions

  1. Preserved historical output. The surviving December 23, 2024 BEREC classification artifact is preserved unchanged in output/BO1A-2024-12-23-55_cat.txt.

  2. Best-evidenced December 23 reconstruction. The reconstructed historical-family condition uses BO1B.txt, the best-evidenced reconstructed December 23 prompt configuration, and the pinned gpt-4-turbo-2024-04-09 model. This is explicitly a reconstruction, not an exact-replication claim.

  3. Retrospective December 24 SBS application with GPT-5.4 nano. The recovered December 24 SBS protocol is applied to BO1B.txt using the pinned gpt-5.4-nano-2026-03-17 snapshot.

The derived comparison tables below are generated locally from those artifacts. No API calls are made during this analysis.

Agreement across conditions

The best-evidenced GPT-4 Turbo reconstruction reproduces 13 of the 15 classifications in the preserved historical BEREC artifact, corresponding to 86.7% classification agreement.

The preserved historical artifact and the GPT-5.4 nano SBS run agree on 10 of 15 classifications (66.7%). The reconstructed GPT-4 Turbo condition and the GPT-5.4 nano SBS condition also agree on 10 of 15 classifications (66.7%).

These percentages describe classification agreement, not accuracy. The preserved historical artifact is an observed historical output, not a validated ground-truth coding of BEREC.

Question-level comparison

Historical artifact versus reconstructed GPT-4 Turbo

The best-evidenced December 23 reconstruction differs from the preserved historical artifact on only two questions:

  • Q4: preserved TRUE; reconstructed GPT-4 Turbo FALSE.
  • Q12: preserved FALSE; reconstructed GPT-4 Turbo TRUE.

The two conditions therefore have the same overall response prevalence—8 TRUE and 7 FALSE classifications—but disagree on two individual classifications.

Reconstructed GPT-4 Turbo versus GPT-5.4 nano SBS

Relative to the reconstructed GPT-4 Turbo condition, the GPT-5.4 nano SBS run changes five classifications:

  • Q1: TRUE → FALSE
  • Q2: TRUE → FALSE
  • Q7: TRUE → FALSE
  • Q8: TRUE → FALSE
  • Q12: TRUE → FALSE

All five changes occur in the same direction. The reconstructed GPT-4 Turbo condition contains 8 TRUE classifications, whereas the GPT-5.4 nano SBS condition contains 3.

Interpretation

The BEREC reconstruction provides useful evidence about the recoverability of the historical classification pattern. Under the best-evidenced December 23 configuration, the pinned GPT-4 Turbo snapshot reproduces 13 of the 15 classifications present in the preserved historical artifact.

That result should not be interpreted as an exact replication of the historical API interaction. The surviving evidence does not establish every element of the original BEREC request strongly enough to make that claim.

Likewise, the five differences between the reconstructed GPT-4 Turbo condition and the GPT-5.4 nano SBS condition cannot be attributed exclusively to model change. Those conditions differ in both model and reconstructed protocol.

For this reason, BEREC remains an auxiliary provenance and reconstruction analysis and is not added as a sixth organization to the principal five-PON model comparison.

Provenance

The preserved historical artifact remains read-only. Both reconstruction runs were written to new timestamped directories under output/berec_replication/.

The numerical results on this page are read from:

  • derived/berec_three_way_comparison.csv
  • derived/berec_three_way_summary.csv
  • derived/berec_sources.csv

These files are generated by:

python scripts/08_compare_berec.py

That script performs local comparison only and makes no API calls.
